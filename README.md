# PhD thesis — optimisation and comparison of urban cycling networks

Code, data and figures of the papers of the PhD thesis of **Manuel Campero Jurado**
(with C. Canudas-de-Wit, G. De Nunzio and M. Salazar).
Each folder is a self-contained project for one paper: its own code, data, results, figures,
README and a `run_all.py` that runs every step in order.

| Folder | Paper | Topic | Environment |
|---|---|---|---|
| [`T_ITS_2025/`](T_ITS_2025) | *A Graph-Based Approach to the Topological Optimization of Cycling Networks for the Improvement of Safety and Comfort of Cyclists* (IEEE T-ITS) | graph metrics of 14 French cities, safety/comfort prediction model, MLCC vs GA vs Bayesian optimisation | `cycling-tits` |
| [`ECC_2025/`](ECC_2025) | *A bi-level optimization framework to upgrade cycling infrastructure by degree of separation (DoS)* (ECC 2025) | cyclist routing + DoS upgrades of Grenoble, MLCC vs GA | `cycling-ecc` |
| [`CDC_2025/`](CDC_2025) | *Optimal bike network design in line with principles of justice* (CDC 2025) | utilitarian vs sufficientarian upgrades | `cycling-ecc` |
| [`ITSC_2025/`](ITSC_2025) | *Safety-Oriented Design of Cycling Infrastructure Minimizing Impact on Vehicular Traffic* (ITSC 2025) | two-layer bike + car network, car user equilibrium, Pareto trade-off | `cycling-ecc` |
| [`T_ITS_Special_Issue/`](T_ITS_Special_Issue) | *Justice-informed Cycling Infrastructure Upgrade via Multi-modal Bi-level Optimization* (T-ITS Special Issue) | mode choice, UE surrogates (ridge / GNN), justice-informed GA | `cycling-ecc` |
| [`ITSC_2026/`](ITSC_2026) | *Mathematical comparison of urban cycling networks via safety-aware clustering* (ITSC 2026) | safety-aware clustering (CC-Algorithm) vs k-means, Gromov–Wasserstein comparison of Grenoble, Lyon, Strasbourg | `cycling-ecc` |
| [`T_ITS_2026/`](T_ITS_2026) | *Mathematical Comparison and Optimization of Urban Cycling Networks via Safety-Aware Clustering* (IEEE T-ITS) | journal version of ITSC 2026 + optimisation on clustered networks and strategy transfer | `cycling-ecc` |

## How to run a project

```bash
git clone https://github.com/leunamCampero/PhD_tesis.git
cd PhD_tesis/ECC_2025                     # any project folder

conda env create -f environment.yml       # once per environment (cycling-ecc or cycling-tits)
conda activate cycling-ecc

python run_all.py --list                  # the steps, in order, with their run times
python run_all.py                         # run them all  (or: --from N, --only N, --skip N)
```

The steps can also be run one by one (`python 01_….py`, `python 02_….py`, …); the README of each
project explains what every step computes, the parameters (`src/<package>/config.py`), the outputs and
the figures. `T_ITS_2025` uses Jupyter notebooks (`notebooks/01 … 06`) instead of scripts.

Results and figures of a complete run are already included (`results/`, `figures/`), so a project can
be inspected without running anything. Long steps (genetic algorithms, user equilibria) take from
minutes to hours; the run time of each step is given in `run_all.py --list`.

> **Windows:** run the scripts from an *activated* conda shell (Anaconda Prompt, or a terminal where
> `conda activate` was run). Calling the environment's `python.exe` directly can crash scipy/matplotlib
> because other programs on the PATH ship conflicting DLLs.

## Layout of every project

```
<PROJECT>/
├── README.md            what the paper does, how to run it, parameters, outputs
├── environment.yml      conda environment
├── run_all.py           runs all the steps in order
├── 01_….py, 02_….py …   the steps (run in numerical order)
├── src/<package>/       the library (config.py holds all the parameters)
├── data/                input data (networks, demand, …)
├── results/             tables, logs and intermediate results written by the steps
├── figures/             figures written by the steps (PNG + PDF)
├── tests/               unit tests (python tests/run_tests.py), where available
├── tools/               one-off helper scripts (data conversion, Windows runner)
└── paper/               LaTeX source and PDF of the paper
```

## Not in this repository

* `_archive_old_files/` of each project: the original working notebooks and legacy pickles
  (several GB). They are kept on the author's machine only; none of the steps needs them
  (the data they produced is in `data/`).
* `T_ITS_Special_Issue/results/05b_arrays.npz` (~250 MB, above GitHub's file limit): regenerated by
  step `5b` of that project (~20 min) before its figures step.
